## @MappedSuperclass

- 상속 관계 매핑과 관계 없음

- 공통 매핑 정보가 필요할 때 사용한다.

- 단순하게 객체 입장에서 id, name이라는 필드가 계속 반복된다.

- 귀찮아서 이걸 부모 클래스에 두고 따로 여러번 쓰고 싶음

- 이 귀찮음을 줄이고자 사용

## 예시

- member, seller 등 여러 테이블에서, 공통으로 사용하는 필드가 있는 상황

```java
 //반복되는 무언가
private String createdBy;
private LocalDateTime createdDate;
private String lastModifiedBy;
private LocalDateTime lastModifiedDate;

```

- 이런 필드를 모든 클래스에 집어 넣고, 관리해야 한다.

- 하지만 귀찮다.

- 이때 사용하는게 @MappedSuperclass

- BaseEntity라는 새로운 클래스를 생성, 공통 반복되는 필드와 getter/setter를 작성한다.

- 해당 클래스 위에 @MappedSuperclass 만 붙이고, 다른 클래스에서 이 BaseEntity를 extends 하면,

- 공통 속성들이 테이블 생성에 추가된다.

## 주의

- 상속관계 매핑이 아니다.

- 엔티티가 아니다. 테이블과 매핑되는게 아니다.

- 부모 같지만 부모 아님(조회 불가)

- 직접 생성해서 사용하지 않기 때문에 `추상 클래스`로 사용

- 매핑 정보만 제공하는 것

- 테이블과 관계 없이 엔티티가 공통으로 사용하는 매핑 정보를 모아놓은 역할

- 주로 등록일,수정일, 등록자, 수정자
