## 즉시 로딩과 지연 로딩

- Member 조회할 때 Team을 같이 조회해야하나

- 지연 로딩 Lazy를 사용하는 옵션을 JPA가 제공

```java
//지연로딩 세팅
@ManyToOne(fetch = fetchType.LAZY)
```

- 이렇게 두면 em.find로 Member를 가져올 때 team은 안가져온다.

- 대신 프록시로 둔다.

- 나중에 team.getName() 같이 실제 값을 사용하려 할 때 실제 team으로 프록시 객체를 초기화한다.

### 전체 코드 보니 멤버랑 팀을 항상 같이 쓴다면?

- 즉시 로딩을 하자

```java
//지연로딩 세팅
@ManyToOne(fetch = fetchType.EAGER)
```

- 쿼리가 member만 조회할 때 team 싹 조회

- 즉시 로딩이기 때문에 프록시가 필요 없음 - 애초에 진짜 엔티티 객체가 온것

## JPA 구현체는 한번에 join 쿼리를 날려서 member, team 가져온다.

## 주의

- 실무에서는 즉시 로딩은 쓰지 마라

- 가급적 지연로딩을 사용

- 즉시 로딩을 쓰면 예상하지 못한 SQL이 발생한다.

- member를 find 하고 있는데, 수십개의 join을 하고 있다면?

- 테이블이 얽혀있다면 지연로딩을 써라

### JPQL에서 N+1 문제 일으킨다.

```java
em.createQuery("select m from Member m", Member.class)
    .getResultList();
```

실행 하면, 쿼리가 2번 나간다.

- em.find는 PK를 찍어서 하는 거기 때문에 SQL 한번이면 된다.

- JPQL은 즉시로딩일 때 값이 다 차있어야 한다.

- Select \* from Member로 번역이 된 것을 db에 보낼 텐데, Member에 team 이 있음

- select \* from team where team_id == xx 도 나가야 한다.

- 쿼리를 하나 날렸는데, 관련된 테이블 N개 만큼 추가 쿼리가 나간다.

- @ManyToOne, @OneToOne 은 디폴트가 즉시 로딩이다. -> lazy로 바꿔놔야 한다.
