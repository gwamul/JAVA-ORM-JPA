## 값 타입과 불변 객체

- 값 타입 : 복잡한 객체 세상을 조금이라도 단순화 하려고 만든 개념

- 안전하고 단순하게 다룰 수 있어야 한다.

## 값 타입 공유 참조

- 회원1, 회원 2가 같은 값 타입을 공유하고 있다면?

- M1, M2가 같은 값 타입 주소 를 가리키고 있다면?

- 나중에 M1의 주소를 새롭게 바꾸는 일이 발생.

- 그럼 주소 Address 인스턴스의 city 부분이 변경되고, 그 변경된 내용이 M2에 영향을 줄 수 있다.

- 값 타입은 온전해야 한다.

### 공유해서 쓰도록 의도한 경우 : 값 타입이 아닌 엔티티를 써야 한다.

- 제대로 쓰는 경우 : 복사해야 한다.

```java
Address copyAddress = new Address(address.getCity(), address.getStreet(), ...);
```

- 이렇게 복사해야 한다.

- 만약 복사하지 않고 그대로 쓴다면, 컴파일러 단에서는 알 방법이 없다.

## 객체 타입의 한계

- 항상 값을 복사해서 사용하면 공유 참조로 인해 발생하는 부작용 피할 수 있다.

- 문제는 임베디드 타입같이 직접 정의한 값 타입은 `객체 타입`

- 객체 타입은 참조값을 직접 대입하는 것을 막을 수 없음(타입만 맞으면 다 들어간다.)

## 불변객체

- 객체 타입을 수정할 수 없게 만들면 그 부작용을 원천 차단할 수 있다.

- 값 타입 : 불변 객체로 설계해야 한다.

- 불변 객체 : 생성 시점 이후 절대 값 변경 못하는 객체

- 생성자로 생성, Setter 안만든다.

- 불변 제약으로 부작용을 막을 수 있다.

## 값을 바꾸고 싶은 경우

- Setter()를 다 지워 버렸다.

- 근데 바꾸고 싶은 경우. 새롭게 만들어야 한다.

```java
Address address = new Address(asd, asdf,asd );
// 이렇게 만든 address 의 값을 바꾸고 싶다면...

Address newaddress = new Address(asd, asdf,asd );
//이렇게 새로 만들어서 다시 넣는다.
```
